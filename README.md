# PATIENT ZERO — 최초 감염자

**묻는 것:** 감염을 *퍼뜨리는 쪽*에 앉히면, 좀비 서바이벌은 어떤 게임이 되나?

설치나 빌드 없이 `index.html`을 열면 실행됩니다. 폰 **가로 화면 전용**입니다 —
PC 에서 파일로 열면 폰 미리보기(`phone.html`)로 자동으로 넘어가, 실제 기기 CSS 크기 그대로
아이폰·갤럭시 가로 화면을 띄웁니다. 폰을 세로로 들면 판이 멈추고 돌려 달라고 합니다.

어두운 애니메이션풍 도시 아트, 붉은 감염 효과, 푸른 백신 사격, 실시간 미니맵.
일러스트와 투명 캐릭터 아틀라스는 생성 파이프라인으로 만들어 `assets/` 에 넣었고,
제작 프롬프트는 [`ART-DIRECTION.md`](ART-DIRECTION.md) 에 있습니다.
사선 도시 배경 위에 2D 캐릭터와 파티클을 합성하는 Canvas POC 이며 실시간 3D 렌더러가 아닙니다.

## 한 판의 모양 — 90초, 챕터 하나

한 판은 **90초로 고정**입니다. 그 안에 챕터의 **통과선**(감염 인원)을 넘기면 그 자리에서 통과하고,
다음 챕터가 열립니다. 통과한 뒤 남은 시간은 전부 **기록 경신**에 씁니다 — 깨는 것과 기록을 미는 것이
같은 한 판 안에 들어 있습니다. 모든 판이 같은 90초이므로 같은 챕터 안에서는 기록을 그대로 견줄 수 있습니다.

챕터 9개는 **어려워질수록 기록이 쉬워지도록** 두 축을 같이 올립니다.

| | 1 첫 접촉 | 3 통제 불능 | 5 봉쇄선 돌파 | 7 정전 | 9 최초 감염자 |
|---|---|---|---|---|---|
| 통과선 | 25명 | 55명 | 95명 | 140명 | 195명 |
| 동시 인파 | 34명 | 50명 | 66명 | 82명 | 100명 |
| 첫 백신 | 10초 | 6초 | 4초 | 3초 | 2초 |
| 백신 최대 | 4명 | 6명 | 8명 | 10명 | 12명 |

백신은 빨라지고 많아지지만 인파도 같이 쏟아지므로, 뒤 챕터일수록 **점수의 천장이 높습니다**.
챕터마다 별 셋(통과선 / ×1.35 / ×1.75)과 최고 기록을 따로 셉니다.

## 화면

한 화면이 곧 게임판입니다. 웹페이지 장식(사이드바·브리핑·푸터)은 없고, UI 는 네 귀퉁이에만 있습니다.

| 자리 | 무엇 |
|---|---|
| 왼쪽 위 | 남은 시간 · 챕터/위협 단계 · 감염 인원과 통과선 막대 · 별 · 체력 · 연쇄 |
| 오른쪽 위 | 미니맵 · 일시정지 |
| 왼쪽 아래 | 이동 스틱 (엄지) |
| 오른쪽 아래 | 대시(큰 원) · 방어막 · 충격파 |
| 로비·일시정지 화면 | 챕터 · 아이템 · 내 기록 · 조작법 |

시간은 흐르지 않고 **줄어듭니다**. 10초가 남으면 숫자가 붉게 뛰고 초읽기가 울립니다.
세계 비율은 화면 비율을 따라가므로 가로 화면이면 레터박스가 생기지 않습니다.

## 조작

- 왼쪽 스틱을 끌어 이동. 사람과 접촉하면 1명 감염. (키보드: WASD / 방향키)
- 큰 원 버튼: 2.3초마다 무적 돌진. 덮개가 내려가면 충전 완료. (SPACE)
- 방패 버튼: 3초간 백신 차단. 초기 2개. (Q)
- 번개 버튼: 반경 300 내 백신 탄환 제거, 발사자 2.5초 지연. 초기 1개. (E)
- 오른쪽 위 Ⅱ: 일시정지. 다른 창으로 전환하거나 폰을 세로로 돌려도 자동 일시정지. (ESC / P)

백신은 피격당 20 피해를 주며, 체력이 0이 되면 90초를 다 채우지 못하고 끝납니다.
2.8초 안에 연속 감염하면 연쇄가 이어지고 3연쇄부터 감염마다 체력 2를 회복합니다.

**퍼뜨리는 건 오직 당신입니다.** 감염된 사람은 자기 옷을 입은 채 변해(전용 감염자 원화) 비틀대며
가장 가까운 테두리로 걸어 나갑니다 — 남을 감염시키지 않고, 당신이 한 일의 흔적으로만 남습니다.
인파는 챕터의 목표 인원에 맞춰 모자란 만큼 즉시 채워지므로 빈 광장에서 끝나는 판은 없습니다.
보급품은 10초마다, 추가 아이템은 12명 감염마다 생성됩니다.

챕터별 최고 기록과 통과 여부는 현재 브라우저 localStorage 에 저장됩니다. 상대는 AI 이며
실시간 멀티플레이와 온라인 랭킹은 이 POC 범위 밖입니다.

## 아이콘 · 스토어 이미지 · 티저 (2026-10-14)

앱 아이콘은 「막차 이후」와 같은 방식으로 만들었습니다 — **대표 캐릭터의 얼굴 한 장**을 생성 파이프라인으로
굽고(제로 LD + 로비 키 아트를 레퍼런스로), 거기서 쓰이는 모든 크기를 잘라냅니다. 글자는 넣지 않습니다.

```

node tools/bake-icon.mjs     # → icons/ (16·32·48·180·192·512·maskable·favicon.ico) + icons/store (1024·적응형)
node tools/store-shots.mjs   # 스토어 스크린샷 5묶음 30장 — 실제 게임을 켜서 찍는다
node tools/gen-promo.mjs     # 홍보 원본 한 장 (생성)
node tools/store-promo.mjs   # → site/ 의 요구 화소들 (피처 그래픽 · 헤더 · 검색 결과)
node tools/store-check.mjs   # 전부 다시 재고 site/manifest.json — 어긋나면 실패한다

# 영어판 (스토어 목록은 언어마다 스크린샷이 따로다)

node tools/store-shots.mjs --lang en          # 영어 5묶음 (--shot 04,06 으로 몇 장만 다시)
node promo/capture.mjs --lang en && node promo/render.js --lang en --frames --workers 4
```

제출 묶음과 규격표는 [`site/README.md`](site/README.md), 20초 티저는 [`promo/README.md`](promo/README.md) 에 있습니다.
**출시 자체**(이름·번들 ID·상품 ID·원고·심사 답변·남은 일)는 [`STORE.md`](STORE.md) 한 장에 모아 두었습니다.
**애플은 알파 채널이 있는 아이콘을 거부**하므로 배경색으로 눌러 두고, 안드로이드 적응형만 알파를 남깁니다.

## 챕터 선택 — 목업 1:1 (2026-10-14)

받은 목업은 **1404×790(16:9)** 이다. 그 자를 그대로 쓰되, 가로는 비율로 늘이지 않는다.

- `--u = 화면 높이 / 790`. 목업에서 잰 좌표에 `--u` 를 곱한다. 790 높이에서는 `--u = 1px` 라 **목업과 같은 픽셀**이 나온다.
- 가로는 **귀퉁이에 붙인다.** 왼쪽 덩어리는 `left`, 오른쪽 덩어리는 `right`, 카드열과 단계 표시만 가운데.
  폰 가로(2.1:1)는 16:9 보다 납작해서, 가로까지 같이 늘이면 머리와 기록판이 가운데로 말려 들어온다.
- 작은 화면에서는 글자 최소 크기(`max(8px, …)`)가 상자보다 커진다. 그래서 대사·기록판·미리보기·잠금 딱지는
  `width:max-content` 로 **늘어나게** 뒀다 — 줄바꿈 대신 자리를 내준다.

화면에 있는 것: 머리줄(‹ · 챕터 선택 · 홈) · 두 줄 대사 · 감염자 수 기록판 · 모서리 닫기 ·
카드열(옆 268×414, 가운데 356×480, 간격 16) · 좌우 화살표 · 손글씨 표어 · 단계 다섯 · 다음 챕터 미리보기 ·
아래 메뉴 넷 · INFECTION 로고.

**출격 버튼은 없다.** 목업에 없어서 뺐다 — 가운데 카드를 한 번 더 누르면 그 챕터로 출격한다.
옆 카드를 누르면 가운데로 온다. 나갈 때 보고 있던 챕터를 그대로 들고 나간다.

### 여기서 두 번 데었다

1. **가운데 카드가 자라는 동안 재면 안 된다.** 카드 폭을 268→356 으로 애니메이션하면서
   `scrollIntoView` 를 부르면, 다 자란 뒤 폭의 절반(44px)만큼 어긋난 채로 스냅된다.
   크기 애니메이션을 빼고, 다 자란 뒤의 자(슬롯 간격 284)로 `scrollLeft` 를 직접 센다(`railCenter`).
   손가락으로 넘긴 뒤 어느 카드인지 고를 때도 **같은 자**를 쓴다 — 폭을 재서 고르면 또 어긋난다.
2. **`hidden` 은 `display:flex` 를 못 이긴다.** 창 밖 단계와 접어 둔 기록이 그대로 보였다.
   `[hidden]{display:none!important}` 를 한 줄 넣어 끝냈다.

| `chapter-bg` | 뒤에 깔리는 부서진 도시. 가리는 건 글자가 앉는 띠와 귀퉁이뿐 — 목업처럼 **배경이 보여야 한다** |
| `card-frame` · `card-scratch` | 가운데 카드의 찢긴 종이 테두리와 그 위에 그은 붉은 틀 (두 장으로 나눠야 빨강을 종이 위에 올릴 수 있다) |
| `chapter-slogan` | 「더 많은 감염을, 더 높은 기록을.」 손글씨 + 붉은 획 |
| `chapter-logo` | 오른쪽 아래 INFECTION 마크 |
| `title-slash` · `claw-mark` | 제목 밑 붉은 획, 단계 표시의 흰 할퀸 자국 |
| `reward-crate` | 보상 칸의 보급 상자 |
| `poster-1…19` | **챕터마다 제 포스터.** 전투 바닥판(`map-*`)은 위에서 내려다본 판이라 세로 카드에 세우면 바닥만 보인다 |

포스터는 **가까운 것만 받는다.** 가운데에서 ±4 칸인 카드와 보이는 단계 다섯 개만 그림을 붙이고,
넘기면 그때 마저 받는다 — 열자마자 19장(1.2MB)을 받던 걸 7장(430KB)으로 줄였다.
`loading="lazy"` 로는 모자랐다: 카드열 전체가 화면 세 배 폭이라 크롬이 그냥 다 받는다.

글씨 그림(한글 포함)도 생성이 된다. 다만 **획이 두꺼우면 작게 줄였을 때 뭉친다** — 밑줄 하나 굽는 데
「이미지 높이의 1/12 두께에서 오른쪽 끝까지 가늘어지는 획 하나」까지 적어야 목업처럼 나왔다.

### 카드에 사람을 오려 붙이지 않는다

포스터 한 장이 곧 카드다. 캐스트 LD 를 카드 위에 얹어 봤지만 그림 두 장이 따로 놀았다.
보상도 **모집권뿐**이다 — 챕터를 깨서 실제로 나오는 게 그것뿐이라, 목업에 있던 조각과 캐릭터 칸은 뺐다.

**캐릭터 선택**은 왼쪽 42% 가 반신 원화다. 그 위에 등급·이름·로마자·별·대사 인용·CV,

`progression.js` 는 건드리지 않았다. 시안에만 있고 기존 markup 에 없던 것
(로마자·대사·CV·탭·NEW 딱지·화살표)은 `js/character-screen.js` 가 **얹는다** —
그쪽이 `#dialog-content` 를 통째로 다시 쓰는 걸 `MutationObserver` 로 지켜보다 매번 다시 얹는다
(필터·정렬·카드 선택 때마다 새로 그린다). 나머지 모양새는 전부 `style.css`.

- 로마자는 **id 가 곧 로마자**라 표를 따로 두지 않는다 — `sera` → `SERA`.
- 인용은 그 캐릭터의 첫 대사, 스토리 탭은 **그다음 줄부터**(같은 말을 두 번 쓰지 않게).
- `NEW` 는 **진짜 새것**일 때만 — 가지고 있는데 이 화면에서 아직 안 본 캐릭터(`patient-zero-seen-v1`).
  `특별 모집` 은 `limited` 인 레아. 시안의 `Lv.1` 은 **안 적는다** — 이 게임에 캐릭터 레벨이 없다.
- 함정: `.character-keyart-caption` 바탕 규칙이 `bottom:0` 이라 `top` 만 주면 칸이 아래까지 늘어나
  탭과 184px 겹친다. `bottom:auto` 로 풀어 줘야 한다. 세로 420 아래에서는 대사·CV 를 접는다.

**랭킹**은 탭 둘. `내 최고 기록` 은 챕터별 기록과 최근 작전, `유저 순위` 는 **챕터를 가리지 않고
가장 높은 기록 하나**로 줄을 세운다(어느 챕터에서 냈는지는 옆에 적는다).

아직 계정·기록 서버가 없어서 유저 순위에는 **이 기기의 기록만** 선다 —
없는 상대를 지어내 채우지 않고, 왜 비었는지 그대로 적는다.
서버가 생기면 `js/ranking.js` 맨 위 `ENDPOINT` 한 줄만 채우면 된다
(`GET` 은 `[{name,score,chapter}…]`, `POST` 는 `{name,score,chapter}`).

## 사진 모드 (2026-10-14)

스크린샷 찍으라고 있는 것. 화면 아무 곳이나 누르거나 `H`·`ESC` 로 돌아온다.

그래야 나중에 로비에 칸이 늘어나도 사진에 끼어들지 않는다. `test/photo-test.cjs` 도 같은 방식으로
**직계 자식을 전부 훑어** 투명한지 보므로, 새 칸을 추가하고 깜빡해도 테스트가 잡아 준다.

구현은 `js/photo.js` 하나에 들어 있고 제 단추와 덮개를 스스로 만들어 붙인다 — 로비 markup 과
`game.js` 는 건드리지 않았다. 사진 모드인 채로 출격했다가 돌아오면 자동으로 풀린다(안 그러면 UI 없이 갇힌다).

## 소리 (2026-10-14)

**브금 두 벌**과 **감염·피격 효과음**. 오디오 파일은 하나도 없다 — 전부 Web Audio 로 그 자리에서 합성한다
(`playground/music/` 시리즈와 같은 방식). 폰이 받는 양은 0바이트고, 똑같이 반복되는 구간이 없다.

| | |
|---|---|
| 항시 (`js/bgm.js`) | A단조 펜타토닉. 디튠한 드론 + 28초 주기로 숨 쉬는 필터 + 4~9초마다 울리는 종 |
| 전투 | 124BPM 16스텝. Am–F–Dm–E 네 마디, 킥·하이햇·톱니 베이스·사각파 아르페지오 |
| 감염 (`js/sfx.js`) | 연쇄가 쌓일수록 반음씩 올라간다 |
| 피격 | 저역 몸통 + 320→150Hz + 잡음 한 조각 |

이 시리즈에서 처음 하는 것: **게임 상태를 듣는 음악.** 전투 벌의 세기(0~1)가 남은 시간·통과선까지의 거리·
챕터 난이도에서 실시간으로 나오고, 쫓길수록 필터가 열리고 아르페지오가 붙는다.
`body[data-mode]` 만 보고 움직이므로 `game.js` 는 건드리지 않았다. 설정의 **배경음악** 칸으로 따로 끌 수 있다.

### 여기서 셋을 고쳤다

1. **효과음이 꺼진 채로 시작했다.** `sound = false` 로 두고 옛 키(`patient-zero-sound`)가 `'true'` 일 때만 켰는데,
   처음 켠 사람에겐 그 키가 없다 — 설정은 「켬」인데 소리는 **하나도 안 났다.** 이제 설정을 따른다.
2. **연쇄 중에는 공격음이 없었다.** `if (!chained)` 로 막혀 있어서 정작 핵심 고리가 조용했다.
3. **피격음이 70Hz 였다.** 폰 스피커가 내주지 못하는 대역이라 통째로 안 들렸다 — music/ 시리즈의 교훈 그대로
   220Hz 위 레이어를 섞었다. `test/bgm-test.cjs` 가 300Hz 위 에너지 비율을 **재서** 다시 그러지 못하게 막는다.

### 검증

브금·효과음은 귀 대신 **자로 잰다.** 브라우저의 `OfflineAudioContext` 로 `js/bgm.js`·`js/sfx.js` 그 코드를
그대로 렌더해 초당 RMS(무음 구간), 피크(클리핑), 300Hz 위 에너지 비율, 50ms 창의 출렁임(박자 유무),
세기 0→1 의 밝기 변화를 본다. 목업이 아니라 실제 코드라 **시험에서 잰 것이 실제로 나는 소리**다.
`node tools/render-bgm.mjs` 로 두 벌을 WAV 로 구워 들어 볼 수도 있다(저장소에만 두고 배포에는 안 올라간다).

## 로비 대시보드 / 개인 프로필

배경과 선택 캐릭터 아트는 유지하면서 프로필, 상단 재화, 우편함·알림·설정, 왼쪽 메뉴, 챕터·수집 이벤트·일일 임무, 하단 메뉴와 공지·모집·스토리 배너를 연결했습니다. 실제 모집권/조각만 표시하며 가상 재화나 기간은 추가하지 않았습니다.

프로필은 닉네임(16자), 소개(80자), 보유 캐릭터 중 대표 사진을 저장합니다. 사진은 전투 캐릭터와 독립적입니다. 작전 완료마다 감염 수 + 생존 3초당 1 + 완주 50 경험치를 얻고 100 경험치마다 레벨이 오릅니다. 누적 통계는 기능 도입 이후부터 집계하며 최고 기록과 챕터 클리어는 기존 기록을 사용합니다. 프로필과 읽음 상태는 `patient-zero-profile-v1`에 저장됩니다.

상시 수집 이벤트: 캐릭터 5/10/20명 보유 시 모집권 3/5/10장을 한 번씩 수령. 우편함은 게임 내 공지, 알림은 실제 받을 수 있는 보상을 안내합니다. 하단 교환소는 기존 조각 교환 인벤토리로 연결됩니다.

검증: `node test/dashboard-test.cjs` (4185 포트). 프로필 저장/재접속/사진 변경, 보상 조건, 공지 읽음, 챕터와 임무 이동, 750×335 배치, 경험치 집계를 확인했습니다.

## 공통 메뉴 UI

`js/panels.js`와 `panels.css`가 아이템·랭킹·이벤트·설정·인벤토리·임무·교환소의 공통 헤더, 지갑, 탐색 메뉴와 반응형 패널을 관리합니다. 각 화면은 기존 기능을 유지하며 별도 렌더러에서 콘텐츠를 제공합니다. 인벤토리는 자원/출격 보급량, 교환소는 조각→모집권 및 미보유 캐릭터 영입으로 분리했습니다. 캐릭터/프로필/모집 창에는 공통 패널 스타일을 적용하지 않습니다.

검증: `node test/unified-panels-test.cjs`, `node test/panel-actions-test.cjs` (4186 포트). 7개 화면 이동, 장비·설정, 랭킹 탭, 교환 차감, 보상 수령/중복 방지, 상점 이동, 작은 가로 화면 넘침을 확인합니다. 테스트 데이터는 격리된 브라우저에서만 생성됩니다.
